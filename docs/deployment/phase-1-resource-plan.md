# Phase 1 AWS resource plan

Status: packaged and validated locally; not deployed.

## Creation mechanism

The resource source of truth is:

```text
serverless.yml
infrastructure/serverless/conditions.yml
infrastructure/serverless/iam.yml
infrastructure/serverless/dynamodb.yml
infrastructure/serverless/queues.yml
infrastructure/serverless/storage.yml
infrastructure/serverless/secrets.yml
infrastructure/serverless/monitoring.yml
infrastructure/serverless/outputs.yml
```

The local package command is:

```powershell
pnpm package
```

This performs both operations:

1. Serverless Framework creates `.serverless/cloudformation-template-update-stack.json`.
2. `scripts/validate-packaged-infrastructure.mjs` validates security and topology invariants.

The future deployment command is:

```powershell
pnpm exec serverless deploy --stage dev --region us-east-1
```

It will create or update the CloudFormation stack `tinkiva-messaging-gateway-dev`. Serverless
Framework v4 can also create or reuse its account-level deployment bucket for packaged artifacts.

## Planned stack inventory

| Type                    | Quantity | Purpose                                          |
| ----------------------- | -------: | ------------------------------------------------ |
| API Gateway HTTP API    |        1 | Public gateway entry point, initially `/health`  |
| Lambda                  |        1 | Health handler                                   |
| Lambda execution role   |        1 | Logs for the health handler only                 |
| DynamoDB tables         |        2 | Control plane and message data                   |
| SQS source queues       |        5 | Inbound, two outbound, app events, and media     |
| SQS dead-letter queues  |        5 | One DLQ per source queue                         |
| S3 buckets              |        1 | Private media and temporary raw events           |
| Secrets Manager secrets |        2 | Authentication pepper and JWT signing key        |
| SNS topics              |        1 | Infrastructure alarms                            |
| CloudWatch alarms       |        5 | Trigger on the first visible message in each DLQ |

Serverless also creates the API stage, route, integration, Lambda permission, and log group.

## Security properties

- DynamoDB uses on-demand billing, encryption, TTL, and production-only deletion protection/PITR.
- SQS uses managed server-side encryption; conversational queues are FIFO.
- Source queues retain messages for 4 days and redrive after 5 receives.
- DLQs retain messages for 14 days.
- S3 blocks every form of public access, enforces bucket ownership, rejects non-TLS access, and
  expires `raw-events/` after 30 days.
- Secret values are generated by CloudFormation and do not appear in source control.
- The health Lambda IAM policy has no wildcard resource.
- Other Lambda roles are deliberately absent until their functions and exact access paths exist.

## Cost posture for an idle development environment

The only predictable fixed charge is approximately USD 0.80/month for two Secrets Manager secrets at
USD 0.40 per secret-month. Other services are usage-based:

- DynamoDB on-demand has no throughput charge at zero traffic; storage still applies.
- SQS has no minimum fee and includes one million requests per month in its free tier.
- Five standard-resolution CloudWatch alarm metrics may fit inside the account-level free allowance
  of ten alarm metrics; availability depends on other alarms in the account.
- S3, Lambda, API Gateway, SNS, logs, and the Serverless artifact bucket charge according to actual
  storage or requests.

Pricing must be checked again immediately before deployment:

- https://aws.amazon.com/secrets-manager/pricing/
- https://aws.amazon.com/sqs/pricing/
- https://aws.amazon.com/dynamodb/pricing/
- https://aws.amazon.com/cloudwatch/pricing/

## Rollback and removal

Normal failed stack updates are rolled back by CloudFormation. Manual rollback uses the previous
packaged source state and another `serverless deploy`.

Do not run `serverless remove` after the gateway stores data without first:

1. Suspending integrations.
2. Exporting or retaining required DynamoDB data.
3. Emptying or retaining S3 objects according to policy.
4. Inspecting all DLQs.
5. Scheduling secret deletion according to the retention policy.
6. Recording the operation in `deployment-history.md`.
